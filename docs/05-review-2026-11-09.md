# NetSteer 架构评审（2026-11-09，v1.17.5 基线）

两轮自审 + 容量审计 + 分级方案，作为 v1.18 前置输入。

## 一、三维度评审结论

### 优雅（及格偏上，在退化）
- 好：零二进制依赖；观测面三通道 auto 降级；数据与代码分离。
- 退化：netsteer.js 2933 行单文件无模块边界（v1.18 加向导/联动卡会破 4000）；
  netsteer-qos 一脚本三职（采样/档位/bench）。

### 健壮（机制层够用，运维层裸奔）
- 实测好：apply 幂等+回读；hotplug 自愈；feed sha256+回滚；SQM prev_script 备份。
- 薄弱（实证）：qos/apply/feed 均无 set -e（错误静默）；无 soak 7×24；
  无 drift 守护（sysfs 被外部改动无人纠正）；单 JS 无白屏防护（v1.16.2 事故类）。

### 扩展性（一条架构错位必须先解决）
- **判定前端锚定**：senseClassify 只在浏览器跑（后端 0 引用），采样也是页面驱动
  （无 sleep 无常驻）——D14 联动不能依赖"有人开着网页"。**v1.18 第一件事 = 判定下沉后端**
  （ash/awk 常驻，前端降纯展示），代价是判定逻辑单测随逻辑走。
- 次要：dnslog 七字段无 schema 版本；无 IPv6 证据链；LuCI 框架 API 耦合（24.10/25.x 双版本验证在 P1）。

## 二、容量审计（"更大带宽/更高流量扛得住吗"）

### 扛得住（有证据）
- 每包开销≈零：mode 切换=纯 uci SQM 参数（layer_cake+带宽%），零自定义规则链；
  P2P=fw4 原生 redirect（8 条静态）。cake diffserv 引擎原生分 tin。
- 观测 payload 有界：conntrack 采样 TOP-200 截断+入站 NAT 流预过滤，rpcd 消息恒定。
- 分类 O(1) map：域名/IP 前端查表，不随规模退化。

### 物理天花板（定位义务，非工程问题）
cake 单队列 qdisc 的 CPU 上限：
| 硬件 | 上限 | 结论 |
|---|---|---|
| 4×A55 (R5C) | ~1G（900M 实跑） | 千兆家庭 ✅ |
| J4125 级 x86 | ~1.5-2.5G | 千兆以上勉强 |
| 2.5G+/万兆 | 需 offload | 与整形互斥，不适合 |

**产品义务**：README/官网公开带宽档位矩阵，诚实声明"≤1G 推荐 / 2.5G 需强 x86 / 万兆不适合"。

### 高流量真实风险
1. conntrack 满表=断网级（OpenWrt 默认 max 小内存 4k-16k，重度家庭可打满）→ 分级方案顺带修
2. dump 尖刺：conntrack -L 全量 dump 5 万 flows ≈ 6s CPU burst，与 cake 抢核
   （当前页面驱动无此问题；**D14 下沉后必须增量事件流 conntrack -E 或低频错峰**——硬约束）
3. 校准冲击：D13 压测窗口内全家业务受影响 → 校准提示+错峰

## 三、设备分级方案（D20）

| 档 | 判定 | 能力 | 表达 |
|---|---|---|---|
| T0 轻量 | 1-2 核 或 ≤256MB | 调度+P2P+轻观测 | SQM 不渲染，如实说设备不适合；识别只展示不联动 |
| T1 标准 | 4 核 ARM / 256-512MB | 全功能 | 当前默认 |
| T2 强 | x86 多核 / ≥1GB | 全功能+高带宽+采样放宽 | TOP-N/频率上调 |

- 判级输入：detect 现有探测 + 内存 + WAN 协商带宽 → uci netsteer.core.tier
- 参数自适应：conntrack_max 按 RAM（修满表风险）/RFS 按核数/校准窗口按档/轮询频率按档
- UI 纪律（D17 延伸）：tier 不上文案，用户语言永远是"您的设备适合/不适合 X"
- 与 P0 向导合并：向导第一步探测=判 tier，推荐配置=tier 档——不是新增流程
