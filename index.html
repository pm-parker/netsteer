NetSteerfor OpenWrt

一个总开关，两种网络体验 —— OpenWrt 的整合网络加速方案

GitHub › 下载 Releases

1. 为什么需要它

家用宽带的真实痛点很少是「带宽不够」，而是：一边下载，游戏和视频会议就卡成 PPT —— 满载时延迟从 5.8 ms 飙到 70+ ms（bufferbloat）；4 核软路由把收包全压在一个核上， 千兆一跑满就丢包；P2P 应用因为 NAT 类型拿不到公网直连。

这些问题在 OpenWrt 上各有一个零散解法（SQM、RPS、fullcone…），但把它们调对、联动、并证明真的有效， 需要读几十页论坛帖。NetSteer 把这一整套收进一个 LuCI 应用：一键体检、场景模式、总开关， 每个数字都是在你自己的设备上实测出来的。

2. 整合了什么

01 · SQM

满载延迟整形（cake）

按你的上行带宽自动配置 cake 队列管理。满载下载时平均延迟 58.6 → 7.8 ms，p99 108 → 14 ms。游戏/会议不再被后台下载拖垮。

02 · RPS

全核分摊收包

把单队列网卡的软中断摊到全部核心，消灭「一个核跑满、其他核看戏」。20 路并发下载实测持续吞吐 +17%。

03 · NAT

P2P 直通（DMZ 型）

为指定设备提供 Fullcone 等效 NAT，游戏主机 / PT / 网心云类应用拿到公网直连能力，ICE 成功率显著提升。

04 · UX

体检 · 场景 · 守卫

一键环境体检并给出两档方案（稳/激进）；游戏/下载/P2P 场景模式一键切换；依赖守卫防止其他包悄悄破坏配置。

总开关：关掉它，先自动测一组「关闭基线」；再打开，面板直接显示 真实 A/B 增益（延迟 ↓%、吞吐曲线 vs 基线点线）。 不承诺固定数字 —— 空载时增益很小就如实显示「持平」，你的设备测出多少是多少。

5. 快速开始

从 Releases 下载对应架构的 APK（aarch64 / x86_64 / arm_cortex-a7 / arm_cortex-a9），推到路由器安装：

# 沙箱/电脑 → 路由器（按架构选包）
scp -O luci-app-netsteer-1.12.4-aarch64_generic.apk root@192.168.1.1:/tmp/

# 路由器上
apk add --allow-untrusted /tmp/luci-app-netsteer-1.12.4-aarch64_generic.apk

# 浏览器打开 LuCI → 服务 → NetSteer
# 第一次进入会引导「一键体检」，随后按建议启用即可

依赖会在体检时自动检测：SQM 需要 sqm-scripts + cake，P2P 直通需要防火墙放行。 缺什么、装什么、影响什么，界面上都会讲清楚 —— 从小白到专家调教用户都能各取所需。

* 取舍：开启 cake 整形后满载吞吐约 −29%（4 核软转发的整形开销，两侧仍远超日常实际用量）、空载延迟有 0.1ms 量级微开销。 宽带速率远高于日常用量时，用峰值吞吐换满载延迟确定性是净赚 —— 总开关随时可关，恢复系统默认。
