# v1.13.0 — Device Priority Channel (Per-device QoS)

## Highlights

A dedicated priority channel for one device (console/PC): all of its traffic enters the high-priority video tin in both cake shaping directions. Designed after ASUS "gaming LAN port" / DUMAOS per-device priority — but we make the mechanism transparent: the page shows real bidirectional per-tin rates (live `tc` counters); enabling adds a Video row you can verify yourself. No black box.

## Added

- **Game channel tab**: one-click enable per device IP; five-state badge with honest degradation (off / prioritized / stale rules / marking missing / SQM not running·bypass / shaping not switched)
- **WAN latency sparkline**: 8s sampling, rolling 5 minutes
- **Bidirectional tin table**: rate, packets, drops per tin for up/down (live from `tc -s`)
- **netsteer-qos**: nftables bidirectional DSCP CS4 marking (forward egress rewrite + ingress hook rewrite); `netsteer-gaming.qos` switches cake to diffserv4 + uplink ack-filter; idempotent reapply, init.d/hotplug self-healing, clean restore of simple.qos on disable

## Measured (NanoPi R5C · OpenWrt 25.12.6 · 1000M/50M PPPoE · cake 900M/48M)

- **Mechanism proven**: marked device packets land in the video tin — kernel counters during a 30M shaped window: downlink video tin +8053 pkts, uplink +300 pkts
- **Bandwidth share (the core value)**: with 30M shaping saturated by 8 bulk flows (100% load), marked-path throughput OFF 0.23 Mbps → ON 0.58 Mbps, **2.47×** (4 rounds, all same direction; method: ICPM flood probe flows, small volume, directional conclusion)
- **Latency (honestly noted)**: at 100% saturation, marked-path ping OFF 5.44ms vs ON 6.10ms (3+3 rounds) — cake's flow isolation keeps saturated latency at ~6ms in both states (vs 58.6ms with no SQM); the 4-tin scheduler costs +0.7ms. **The channel's gain is in bandwidth share and deterministic isolation, not latency** (latency protection is cake's own credit)
- **Quality gates**: 177 unit tests green (v1.12 baseline 138); 4-arch (aarch64_generic / aarch64_cortex-a53 / x86_64 / mipsel_24kc) `apk verify` pass; 12 on-router E2E ALL GREEN (incl. UI toggle round-trip); install/uninstall cycle verified (uninstall restores simple.qos, reinstall loses no state)

## Fixed

- rpcd ACL missing `/usr/bin/netsteer-qos` exec whitelist → UI calls got 403 (fixed + new regression test: ACL vs fs.exec consistency check)
- busybox ping lacks fractional `-i` → probe sampling silently returned zero (switched to `-i 1`)
- Three stale E2E assertions updated (data-sec card selectors, help button location, mobile-context false positive)

## Known limits (also noted in-page)

- IPv4 marking only (console/PC traffic is overwhelmingly v4)
- Requires SQM cake running (balanced / low-latency / P2P modes); turbo mode or master-off degrades the channel honestly
- Steam large downloads from the marked device also ride the priority tin — cake flow isolation keeps game-packet latency unaffected; bandwidth is shared fairly per flow
