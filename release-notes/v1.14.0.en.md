# v1.14.0 — Game Platform Recognition + Environment Adaptation (Universal Home Appliance)

## Highlights

**From this release NetSteer is designed as a universal home solution, no longer bound to any specific network**: on startup the plugin probes its environment (proxy core type, DNS observation surface, egress path) and adapts automatically — you never reshape your network to accommodate the plugin.

Two things landed: ① game platform recognition (which of Steam / Epic / PSN / Xbox… this device is touching right now) ② the environment probing layer.

## Added

- **Game platform recognition (DNS panel)**: live display of game platforms matched among the selected device's active connections (cache-domains open dataset, MIT, 158 suffixes, 22+ platforms). Classification runs in the browser — zero router load
- **Environment probing (`netsteer-qos env`)**: auto-detects three things and caches the result
  - Proxy core: Nikki → OpenClash → bare clash/mihomo, probed in order (by live API, not by config file existence)
  - DNS observation: with a proxy core → connection-table sniffing (SNI/Host, zero config zero logs); without → dnsmasq query log (UI toggle); neither → honestly shown unavailable, priority channel unaffected
  - Probe target: WAN gateway preferred (closer to real egress latency), falls back to public DNS if unpingable; the sparkline labels which target is used
- **Likely-game-device suggestion**: DHCP hostname heuristics (ps/xbox/switch/steam/deck…) — one click fills the device IP, no typing
- **init.d warm-up**: probe result cached at boot in the background; first UI open has zero wait

## Why two observation surfaces (honest note)

In homes with a proxy core, DNS is usually hijacked wholesale by fake-ip mode — dnsmasq sees few real queries. There, SNI sniffing from the proxy connection table is the only reliable surface. Conversely, bare routers have no connection table to read; the dnsmasq query log is the standard path. The two channels see **complementary subsets** (TLS connections vs plaintext queries); the plugin picks per environment and states its boundary honestly in the UI.

## Measured (NanoPi R5C · OpenWrt 25.12.6 · Nikki/mihomo)

- Environment probe: `{"proxy_core":"nikki","dns_observer":"mihomo","probe_target":"115.171.90.1"}` (WAN gateway auto-selected; probe latency 1.7ms vs 5.3ms for the old fixed target)
- End-to-end recognition: after a TLS handshake to `lancache.steamcontent.com`, the hostname appears in sampling and matches the steam category
- DHCP suggestions hit 2 real Xboxes (XBOX / XBOXONE)
- dnsmasq branch: forced switch samples normally (captures direct queries bypassing the hijack), environment self-heals back to mihomo when re-enabled
- Quality gates: 215 unit tests green (v1.13 baseline 177, +38); 13 on-router E2E ALL GREEN; 4-arch `apk verify` pass

## Known limits

- Connection snapshots cover active connections only; sub-second short-lived ones may not appear (observation boundary, noted in-page)
- dnsmasq channel sees plaintext DNS only (DoH/DoT invisible)
- OpenClash secret read relies on its uci fields; deeply customized API ports fall back to the dnsmasq channel (non-blocking)
