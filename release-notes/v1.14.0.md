# v1.14.0 — 游戏平台识别 + 环境自适应（通用家庭方案）

### 版本特色

**这条线起，NetSteer 按「通用家庭方案」设计，不再绑定任何特定网络环境**：插件启动时自动探测所在家庭的路由环境（代理内核类型、DNS 观测面、出口路径），并据此自动调整行为——不要求你改任何配置去迁就插件。

本次落地两件事：①游戏平台识别（这台设备正在访问 Steam / Epic / PSN / Xbox…）②环境自适应探测层。

### 新增

- **游戏平台识别（DNS 识别区）**：游戏通道页实时显示所选设备的活跃连接里命中的游戏平台（cache-domains 开源数据集，MIT，158 条后缀，22+ 平台）。分类在浏览器完成，路由器零负担
- **环境探测（`netsteer-qos env`）**：自动识别三类家庭环境并缓存结果
  - 代理内核：Nikki → OpenClash → 裸 clash/mihomo 依次探测（API 存活为准，不是看配置文件存在）
  - DNS 观测面：有代理内核 → 连接表嗅探（SNI/Host，零配置零日志）；无代理 → dnsmasq 查询日志（UI 一键开启/关闭）；都没有 → 如实显示不可用，不影响加速通道
  - 出口探测目标：自动选 WAN 网关（更贴近真实出口延迟），不可 ping 回退公网 DNS；延迟曲线标注所用目标
- **疑似游戏设备建议**：DHCP 主机名启发式（ps/xbox/switch/steam/deck…），一键回填设备 IP，免手输
- **init.d 开机预热**：环境探测结果开机后台缓存，UI 首开零等待

### 为什么有两种观测面（诚实说明）

有代理内核的家庭里，DNS 查询通常被 fake-ip 模式整体接管——dnsmasq 观测不到多少真实查询。此时走代理连接表的 SNI 嗅探是唯一可靠观测面。反之裸路由器家庭没有连接表可看，dnsmasq 查询日志才是标准路径。两个通道看到的是**互补子集**（前者覆盖 TLS 连接，后者覆盖明文查询），插件按环境自动二选一，边界在页面上如实标注。

### 实测（NanoPi R5C · OpenWrt 25.12.6 · Nikki/mihomo 环境）

- 环境探测：`{"proxy_core":"nikki","dns_observer":"mihomo","probe_target":"115.171.90.1"}`（WAN 网关自动选中；probe 延迟 1.7ms vs 旧固定目标 5.3ms）
- 端到端识别：TLS 握手 `lancache.steamcontent.com` 后采样即出现该主机名并命中 steam 分类
- DHCP 建议实机命中 2 台 Xbox（XBOX / XBOXONE）
- dnsmasq 分支实测：强制切换通道后正常采样（捕获绕过劫持的直连查询），关闭后环境自愈回 mihomo
- 质量门：单测 215 项全绿（v1.13 基线 177，+38）；真机 e2e 13 项 ALL GREEN；4 架构 apk verify 全过

### 已知边界

- 连接快照只含活跃连接，秒级短连接可能不出现（观测边界，页面已注明）
- dnsmasq 通道只能看到明文 DNS（DoH/DoT 查询不可见）
- OpenClash 的 secret 读取依赖其 uci 字段；自定义深度魔改的 API 端口探测不到时回退 dnsmasq 通道（不阻塞）
