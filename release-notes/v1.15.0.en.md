# v1.15.0 — L2 Recognition Layer (IP Ranges + Port Heuristics)

> **Compatibility**: this plugin supports OpenWrt 25.x+ (apk package manager) only. Stable 24.10 and earlier use the opkg/.ipk system — installing the .apk fails with `pkg_init_from_file: Malformed package file`. Run `apk --version` on the router first.

## Highlights

Game platform recognition upgraded to a **three-level chain**: domain (SNI/DNS query name) → bare IP ranges (official data) → well-known ports (official NAT ports). This closes L1's biggest blind spot — **bare-IP direct connections**: real-time console traffic via Steam SDR relay / Xbox Live carries no domain to match; now Valve's officially published relay IP table and platform ports hit directly.

## Why not nDPI

The planned nDPI route was killed by testing: the OpenWrt 25.12 feed `libndpi` package ships only the `.so` library, no `ndpiReader` CLI — using it would mean cross-compiling a tool and shipping binaries for 4 architectures, violating the zero-binary-dependency principle (D2) and raising maintenance cost. The replacement uses pure data files: zero dependencies, zero packet capture, classification still in the browser, zero router load.

## Added

- **Three-level recognition**: chain = domain → IP range → port; detail rows label the hit source (domain / IP range / port)
- **gameips.txt** (Steam ranges from Valve's official SDR API): AS32590 consensus wide ranges (155.133/16, 162.254/16 + 4 more) + partner POP /24 consolidation (19 entries incl. China relays); the generator script ships in-repo for re-pulls anytime
- **gameports.txt** (official docs): 3074 TCP/UDP (Xbox Live / PSN NAT, console class), 3480/tcp (PSN), 27015-27050/udp & 27036-27037/tcp (Steam); **3478-3479 deliberately excluded** (generic STUN/TURN, high false-positive rate) — the trade-off is documented as comments inside the data file
- **Sampling upgrade**: every connection snapshot now carries destination IP / port / protocol; pure bare-IP connections are no longer dropped (they are exactly L2's input)

## Measured (NanoPi R5C · Nikki/mihomo)

- End-to-end: a bare-IP TCP connection to a Steam relay (no domain at all) shows up in sampling as `d=155.133.248.36`, IP-range match hits steam
- UDP: the connection table's `destinationIP` field confirmed populated (real traffic samples); the test UDP packet was rejected by the relay so no end-to-end UDP demo — honestly noted as a boundary
- Quality gates: 242 unit tests green (baseline 215, +27); 13 on-router E2E; 4-arch `apk verify`

## Known limits

- IP-range/port levels available only via the proxy-core observation surface (the dnsmasq channel is domain-only — which it can match by name anyway, smaller blind spot)
- Xbox/PSN/Epic don't publish official IP ranges; no fabricated data — these three are covered by domain + port levels
- IP ranges are snapshot data (generation date & revision in the file header); Steam relay ranges have historically been stable, but that is not a forever promise
