# v1.16.0 — Scene Awareness Engine + Remote Dataset Updates

A productization step benchmarked against cFosSpeed's scene modes and bulk_detect: for the first time the plugin "understands" what the network is being used for right now.

## Scene awareness (D12)

- **Independent detection logic per scene**: gaming (three-level chain hit + light) / meetings (meeting domains + STUN/WebRTC UDP bidirectional signature) / streaming (platform domains + sustained heavy downlink) / download (P2P well-known ports + "game-platform big download" recognition)
- **light/heavy analysis** (cFosSpeed bulk_detect counterpart): a single connection with >5MB downlink and down≫up is bulk — **Steam store downloads no longer misread as game sessions**; a targeted transplant of cFosSpeed's same-protocol light/heavy separation
- **Scoring + user-benefit priority order** (gaming > work > streaming > download), every evidence row explainable (domain/IP range/port/traffic shape, with source labels)
- **Debounce state machine**: two consecutive sampling windows with the same verdict before switching scenes; state shows "confirming: next window"
- Data plane reuses the mihomo connection table (D8 channel, zero added cost); dnslog sampling extended with u/v volume fields (byte counters from the connection table)

## Remote dataset updates (D11)

- Two new data files: `streamdomains.txt` (streaming platform domains — Netflix/YouTube/Twitch/Disney+/Bilibili/iQiyi/Youku/Tencent Video/Douyin/Kuaishou…) and `downloadports.txt` (P2P well-known ports: BT/eMule protocol ports)
- **Maintainer updates data → users pull with one click**: jsdelivr CDN (primary, good CN reachability) → GitHub raw (fallback) → uci custom source (`netsteer.feed.url`, can point at a self-hosted mirror)
- `netsteer-feed {status|check|update|rollback}`; sha256 manifest verification + atomic replace + keep-current-on-failure + one-click rollback; zero jq dependency (TSV manifest, busybox ash compatible)
- UI: dataset version row + "check for updates" button; updates hot-apply (no restart, refresh uses new data)
- Generator `scripts/gen-manifest.py` pins data versions (date + content fingerprint); `tests/unit/feed.test.sh` end-to-end regression (update/idempotency/tamper-reject/rollback)

## Known limits (honest)

- Scene awareness depends on the mihomo connection-table channel (homes with a proxy core); a pure dnsmasq surface has no per-connection volume info — verdicts degrade to domain evidence
- If the data source is fully taken over (manifest+files tampered in tandem), sha256 cannot defend — the threat model is CDN cache corruption / transport errors; signature verification is a future option
- v1.17 route (D13/D14 in the decision docs): line calibration (idle after install → bidirectional load test → auto-write SQM) + scene×mode linkage
