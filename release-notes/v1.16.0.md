# v1.16.0 — 场景感知引擎 + 数据远程动态更新

对标 cFosSpeed 场景模式与 bulk_detect 机制的产品化升级：插件第一次"看懂"你此刻在用什么网络。

## 场景感知（D12）

- **每场景独立判定逻辑**：游戏（三级链命中且 light）/ 会议（会议域名 + STUN/WebRTC UDP 双向特征）/ 流媒体（平台域名 + 大体量持续下行）/ 下载（P2P 知名端口 + "游戏平台大下载"识别）
- **light/heavy 轻重分析**（cFosSpeed bulk_detect 对应物）：单连接下行 >5MB 且 down>>up 判 bulk——**Steam 商店下载不再误判为游戏对局**，这是 cFosSpeed 同协议轻重分离思想的对症移植
- **打分制 + 用户收益优先序**（gaming > work > streaming > download），证据链逐条可解释（域名/IP 段/端口/流量形态，来源标签）
- **防抖状态机**：连续 2 个采样窗口同判定才切换场景，状态显示"防抖中：下一窗口确认"
- 数据面复用 mihomo 连接表（D8 通道零新增开销）；dnslog 采样扩展 u/v 体积字段（连接表 upload/download 字节计数）

## 识别数据集远程动态更新（D11）

- 新增两个数据文件：`streamdomains.txt`（流媒体平台域名，Netflix/YouTube/Twitch/Disney+/B 站/爱奇艺/优酷/腾讯视频/抖音/快手…）、`downloadports.txt`（P2P 知名端口：BT/eMule 协议规范端口）
- **维护者更新数据 → 用户端一键拉取**：jsdelivr CDN（主源，国内可达好）→ GitHub raw（备源）→ uci 自定义源（`netsteer.feed.url`，可指自建镜像）
- `netsteer-feed {status|check|update|rollback}` 四命令；sha256 清单校验 + 原子替换 + 失败保留现状 + 一键回退；零 jq 依赖（TSV 清单，busybox ash 兼容）
- UI：数据集版本行 + 「检查数据更新」按钮，更新后数据热生效（无需重启，刷新页面即用新数据）
- 生成器 `scripts/gen-manifest.py` 固化数据版本（日期+内容指纹）；`tests/unit/feed.test.sh` 端到端防回归（update/幂等/篡改拒绝/回退）

## 已知边界（如实）

- 场景感知依赖 mihomo 连接表通道（有代理内核的家庭环境）；纯 dnsmasq 观测面无连接体积信息，场景判定降级为域名证据
- 数据源若被完全接管（manifest+文件配套篡改），sha256 清单无法防御——威胁模型为 CDN 缓存损坏/传输错误，签名校验是后续可选项
