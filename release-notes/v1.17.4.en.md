# v1.17.4 — Self-built Observation Surface (removes the mihomo hard dependency)

## Problem

Scene recognition's only data source was the mihomo/clash /connections API — stop the proxy core and scene awareness goes blind; the dnsmasq fallback channel has no byte volumes (in proxy-hijacked-53 environments even the query log is empty).

## Self-built surface (modeled on the mihomo connection table, native OpenWrt stack)

- Traffic dimension: conntrack netlink flow table (`conntrack -L`, ~1s per 8k flows; /proc reads take 18s, unusable) — bidirectional byte counters per flow (nf_conntrack_acct auto-enabled), only LAN-initiated outbound flows participate in verdicts
- Domain dimension: dnsmasq query-log reply reverse lookup (where DNS goes through dnsmasq); unavailable under proxies → bare IPs go through IP-range matching
- Channel auto-selection: mihomo present → enhanced use (SNI is most accurate); else conntrack (self-built); else dnsmasq — `uci set netsteer.qos.dns_observer=<auto|mihomo|conntrack|dnsmasq>` can pin it
- Dependency: `apk add conntrack` (auto-degrades if missing, never a hard requirement)

## Detection tightening (new false-positive sources exposed by the conntrack view)

- bulk "heavy downlink = streaming" evidence: restricted to ports 80/443/1935 with downlink dominance (v > u×10) — high volume on random ports is P2P/netdisk distribution, not someone watching video
- Flow-level exclusion for public-service devices (netdisk-share boxes / NAS PT class) can't be perfect — device-level exclusion lists are planned under D14
