# v1.17.4 — 场景感知自研观测面 (解除 mihomo 硬依赖)

## 问题
场景识别的唯一数据源是 mihomo/clash 的 /connections API — 代理核心一停, 场景感知全瞎;
dnsmasq 兜底通道无字节量数据 (在代理劫持 53 的环境连查询日志都是空的)。

## 自研观测面 (参考 mihomo 连接表形态, OpenWrt 原生栈)
- 流量维度: conntrack netlink 流表 (`conntrack -L`, ~1s/8k flows; /proc 读取 18s 不可用)
  — 每 flow 双向字节计数 (nf_conntrack_acct 自动开启), 仅 LAN 发起的出站 flow 参与判定
- 域名维度: dnsmasq query 日志 reply 反查 (DNS 走 dnsmasq 的环境可用); 代理环境拿不到 →
  裸 IP 走 IP 段匹配
- 通道自动选择: mihomo 在场 → 增强用 (SNI 最准); 否则 conntrack (自研); 最后 dnsmasq
  — `uci set netsteer.qos.dns_observer=<auto|mihomo|conntrack|dnsmasq>` 可钉死
- 依赖: `apk add conntrack` (缺失自动降级, 不硬依赖)

## 判定收紧 (conntrack 视角暴露的新误报源)
- bulk "大下行=流媒体" 证据: 仅限 80/443/1935 端口且下行主导 (v > u×10)
  — 随机端口的大流量是 P2P/网盘分发, 不算家里人在看视频
- 对外服务设备 (网心云/NAS PT 类持续大流量) 的 flow 级排除无法完美 — 设备级排除列表规划在 D14

- 真机 conntrack 通道实测: 8.4k flows 全量可见 (mihomo 看不见的直连流量也覆盖)
- e2e 14 ALL GREEN; auto 通道 (mihomo 在场) 域名增强保持
