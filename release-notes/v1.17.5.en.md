# v1.17.5 — Two Copy Fixes (caught from user screenshots)

## 1. Duplicated scene labels

The "recognized" zone showed "Video Call · Video Call", "Video · Video", "Download · netdisk".
Root cause: labels concatenated scene name · evidence category, but evidence without a category fell back to the scene name itself.
Fix: labels now show only the plain scene name + hit count (e.g. "Download · 2 hits"); platform/protocol is internal detail and off the UI; internal English words (netdisk) removed as well.

## 2. "Measured gain" showing higher latency

"Measured gain (vs off baseline): latency ↑39% (5.7 → 7.9 ms)" — a regression labeled a gain, semantically contradictory.
- The arrow/numbers were right (↑ = worse); the flaw was the "measured gain" prefix applied to every outcome
- Common cause of regressions: the 8-second baseline window colliding with background bulk traffic (e.g. a cloud-drive download) queuing pings up
- Fix: on regression the prefix becomes "vs off baseline", honestly reading "latency higher when on", colored neutral gray (no longer green); when >50Mbps bulk traffic crosses the measurement window, "network was busy during measurement, data disturbed" is appended; green "measured gain" appears only for real improvements
- Advice: compare baselines with the network idle, off→on once each; cake's latency benefit mainly shows under congestion — near-equal numbers when idle are normal
