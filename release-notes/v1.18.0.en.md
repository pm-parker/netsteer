# v1.18.0 — Detection Sunk to Backend + First-run Wizard + Scene Linkage

Positioning: the three P0 tasks of v1.18 — detection decoupled from the page, a 3-step usable wizard, scene×mode auto linkage.

## Added

### Detection sunk to backend (b22c808)
- New `sense.awk`: a standalone awk engine, a 1:1 port of the JS verdict rules (three-level chain / volume gates / scoring / prefer-miss)
- New `netsteer-qos sense-daemon`: resident detection daemon, 30s low-frequency polling + 2-window debounce + atomic writes to `/tmp/netsteer/sense.json`
- init.d idempotent start (pid liveness check); **detection no longer breaks when the page closes** — D14 linkage no longer depends on a LuCI page staying open
- `json2tab.awk`: dnslog JSON → seven-field TAB converter (single source shared by netsteer-qos and unit tests)
- Unit tests caught and fixed 3 engine-level bugs: end-of-line gsub stripping empty fields (bare-IP traffic lost) / awk uninitialized subscripts (first port-table row lost) / awk bare VAR not an environment variable (ENVIRON required)

### Frontend consumes backend verdicts (37446ea)
- Scene card reads backend `sense.json` first (trusts backend debounce within a freshness window of `interval*3+10s`, no local second debounce)
- Missing/stale → local detection fallback (original path renamed localSense, behavior unchanged)
- `verdictToRes` top-level pure function: backend ev counts → renderer evidence shape

### Device exclusion + scene linkage (408a8dc)
- `sense_exclude` (uci): sampling filter for excluded devices (the root fix for public-service boxes like cloud-drive miners being misjudged; on-device proof: streaming evidence 1→3)
- `exclude.awk` + the same filter on the JS fallback path
- `sense_linked` (uci, default off): in stable modes (standard/latency), auto-switch by verdict — work/gaming → latency; others → standard; only the standard↔latency band is managed; manual picks (steering/p2p) never overridden; unconfirmed debounce never triggers; verified bidirectionally on-device

### First-run wizard
- New `netsteer-wizard`: probe (hardware detection + concurrent speed-test calibration + tiering) / apply (apply mode + SQM calibrated values + done flag) / skip
- **3-step modal**: Detect → Recommend → One-click enable; upgraders (autotune_done=1) are not bothered again
- **D20 device tiering**: T0 weak devices (≤2 cores or ≤256MB) get pure core-splitting with zero shaping; T1/T2 get "balanced"
- **D13 calibration merged**: 3 concurrent CDN speed tests, 8s window, max throughput ×0.85 written to SQM
- **Speed-test distortion guard**: measured < 1/4 of the line spec (suspected CDN per-connection cap; a gigabit line measured only 24Mbps in tests) switches to a plan-tier picker (100/200/300/500/1000M, nearest tier preselected)
- SQM calibration parameterized: `netsteer-mode` accepts `WIZ_DL/WIZ_UL` env overrides (unset = keep current); also fixed a quote bug in sqm_migrate section-type extraction
- WAN link-speed identification chain: `network.wan.device` → default-route port → physical-port fallback (pppoe virtual ports have no speed file)

## Fixed

- Wizard confirm step rec_ul default filled in (40M)

## Compatibility & upgrade

- apk-only (D18), OpenWrt 24.10+ (apk-managed)
- Detection sinking is transparent to users; upgraders never see first-run popups again
- `sense_linked` defaults off; enable with `uci set netsteer.qos.sense_linked='1'`
- After upgrade the daemon auto-starts via init.d — no manual action
