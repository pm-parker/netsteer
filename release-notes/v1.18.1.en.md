# v1.18.1 — D20 Parameter Auto-tuning + Linkage/Exclusion UI

Positioning: v1.18 scope close-out — Task 4 parameter auto-tuning + Task 3 user-facing linkage/exclusion surfaces.

## Added

### netsteer-tune (D20 parameter auto-tuning)
- New `netsteer-tune <tier|show>`: writes three parameter groups per tier, persisted
  - **nf_conntrack_max scaled to memory** (root fix for table-full outages): `clamp(mem_mb×512, 16384, 262144)` — 128MB→65536 / 256MB→131072 / ≥512MB→262144 cap; buckets=max/4; runtime `sysctl -w` + `/etc/sysctl.d/10-netsteer.conf` replay at boot
  - rfs_sock_flow_entries: T0 16384 / T1 32768 / T2 65536
  - sense-daemon sampling interval: T0 60s / T1 30s / T2 20s (after kill, wait for full exit before restart to avoid idempotent skip)
- Wizard apply calls it automatically (tuned right after tiering); `show` prints current parameters as JSON

### Two new cards on the Smart page (D14 user surface)
- **Auto-switch card**: linkage toggle + one status line ("detecting: video → will switch to low-latency"); user language only, no tier letters; manually chosen P2P/turbo modes explicitly never overridden
- **Excluded devices card**: IP list (tap to remove) + input to add (IPv4 validated); saved entries take effect on the daemon's next sampling round (sense_exclude re-read each round, no reload needed)

## Fixed

- netsteer-tune first-version daemon restart race: init.d idempotent restart saw the not-yet-exited process and skipped relaunch → now waits up to 3s after kill + SIGKILL fallback + pid removal before restart
