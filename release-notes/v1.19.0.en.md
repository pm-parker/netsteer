# v1.19.0 — No-fight Devices (Per-device Bandwidth Arbitration)

## New capability

**No-fight devices** (D22): mark a device's traffic as low priority (DSCP CS1) — it automatically yields when the network is busy: family video and remote access go first; when idle it can still use the full bandwidth. Fit for download boxes, shared-bandwidth boxes (e.g. passive-income miners), NAS sync, and other background devices.

Symmetric to the v1.13 game channel: that one raises a device's priority (CS4), this one lowers it (CS1) — both share the same nft marking pipeline.

## Composition

- `netsteer-bulk`: multi-device list management (add/remove/list/status/off/reapply) + legacy hand-written rule migration detection (`migrate` / `migrate --apply`; understands both `dscp set cs1` and numeric `dscp set 8` spellings)
- New card on the Smart page: device chips (tap to remove), IP add, badge ("on · N devices yielding"), besteffort-mode hint
- **Legacy migration banner**: when hand-written CS1 rules are found under /etc/nftables.d/, the card offers one-click adoption
- **Suggestion engine** (qos suggest): devices continuously saturating the uplink surface in the "possible background hog" strip — one tap to add
- **Game-channel mutual exclusion**: one device cannot be both raised and lowered; hard-checked at script level (ERR: game-conflict)
- boot/hotplug self-healing: rules auto-restore after redial/reboot; rules carry counters, status shows marked packet volume

## How it works

Uplink: nft forward hook (priority -140) marks the source address → WAN cake bulk tin (thresh≈bandwidth/16). Downlink: netdev ingress hook (-440) marks the destination → ifb cake. No SQM script switching — zero intrusion into existing shaping; besteffort mode has no tins (markings saved, effective once back on a diffserv mode; the UI says so).

Measured (miner box .175 continuously saturating a 48M uplink): after CS1 marking, Best Effort backlog 158KB→0, latency 21.7ms→393μs; the box automatically yields into the 3Mbit bulk tin.
