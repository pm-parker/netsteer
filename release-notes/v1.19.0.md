# v1.19.0 — 不抢网设备 (设备级带宽仲裁)

## 新能力

**不抢网设备** (D22)：把指定设备的流量标记为低优先级 (DSCP CS1)，网络繁忙时自动让路——家人看视频、远程访问优先；空闲时它仍可用满带宽。适合下载机、共享盒子 (如网心云)、NAS 同步等后台设备。

与 v1.13 游戏通道对称：那是把设备升优先级 (CS4)，这是降优先级 (CS1)，共用同一条 nft 标记管线。

## 组成

- `netsteer-bulk`：多设备列表管理 (add/remove/list/status/off/reapply) + 存量手工规则迁移检测 (`migrate` / `migrate --apply`，兼容 `dscp set cs1` 与数值 `dscp set 8` 两种写法)
- 智能模式页新卡：设备 chips 点击移除、IP 添加、徽标 (已启用 · N 台让路中)、besteffort 模式提示
- **存量迁移提示**：检测到 /etc/nftables.d/ 手工 CS1 规则时，卡内显示"一键迁入"
- **判定建议** (qos suggest)：持续吃上行的设备自动出现在"发现疑似后台占用"条，点击即加入
- **游戏通道互斥**：同一设备不可同时升/降优先级，脚本层硬校验 (ERR: game-conflict)
- boot/hotplug 兜底：重拨/重启后规则自动恢复；规则带 counter，status 可见标记包量

## 原理

上行 nft forward 钩子 (priority -140) 标记源地址 → WAN cake bulk tin (thresh≈带宽/16)；下行 netdev ingress 钩子 (-440) 标记目的地址 → ifb cake。不切 SQM 脚本，对现有整形配置零侵入；besteffort 模式无 tin (标记保存，切回 diffserv 模式后生效，UI 有提示)。

实测 (网心云 .175 持续吃满 48M 上行场景)：CS1 标记后 Best Effort 队列积压 158KB→0、延迟 21.7ms→393μs，网心云自动让路至 bulk tin 3Mbit。
