# v1.19.1 — Interaction consistency fixes + config write path rebuild

## Fixes

**Root-cause fix for the "auto-switch" error**: on some OpenWrt builds the ubus `uci.apply` method misbehaves (LuCI shows "ubus uci.apply failed: [5]"). This release moves ALL plugin config writes to the uci command-line channel (new `netsteer-cfg` helper — write and commit immediately), eliminating this class of errors for good.

**The "auto-switch" toggle is now part of Smart Mode**: a separate toggle was conceptually redundant — Smart Mode should not ask whether to be smart. With Smart Mode on, scene linking is always active: when someone watches video or plays games the router switches to a better-suited profile automatically, and falls back when idle. Whatever profile you picked manually always wins. One line of explanation in the scene card is all there is — no second switch to understand.

**Also fixed**: scene linking no longer re-enables optimization while the master switch is off (previously a scene change could turn it back on); the Smart Mode page no longer renders a stray "null" text (a widget rendering defect).

## Change details

- New `netsteer-cfg`: unified config-write helper for netsteer (uci set + commit, effective immediately, bypasses the broken ubus apply)
- All 6 frontend config writes migrated to the new channel (scene linking / detection exclude list / device boost / P2P passthrough / autotune flag / bulk devices)
- Scene linking is now on by default (`sense_linked` default 0→1) and never takes over while the master switch is off
- UI: removed the standalone "auto-switch" card; the Smart Scene card gained one line explaining the linking behavior
