# v1.19.3 — Detection engine fixes: L2 classification chain, bandwidth corrosion, DSA adaptation

> The core fixes in this release come from a full-repo code review by external contributor PI-Cursor DS (PR #1), merged after an independent, behavior-level audit by the maintainer.

## Fixes

**P0 · Scene classification: IP-range and port chains never fired**. `sense.awk` had two broken variable chains (the category was written to a function-local variable while the caller read a never-assigned global name), which silenced the entire IP-range and port-rule classification paths — bare-IP direct traffic (the core pattern of gaming and P2P: no domain name, no SNI) could never be classified. After the fix, bare-IP direct connections correctly match game ranges, and non-game IPs are not misclassified. A companion defect in the same code path — the range base value multiplying across records until it overflowed — is fixed as well; even with the category fixed, no range would have matched.

**P1 · Repeated mode switching corrupted bandwidth**. Entering the latency tier wrote bandwidth × 0.9 back without keeping a baseline, so repeated switching kept shrinking the SQM bandwidth (measured −27% over four cycles). The true bandwidth is now archived before the first downshift; both the downshift and the standard-tier restore work from the archive.

**P1 · The "vs baseline" gain layer never rendered**. The throughput chart's gain layer referenced a wrong variable name, producing NaN that the SVG layer silently swallowed. The A/B gain line now draws.

**P1 · netsteer-apply silently ignored arguments**. Every invocation ran a full apply regardless of arguments. It now supports `apply / clear / preset {all|balanced|off} / auto` and rejects unknown arguments with a usage message and exit code 1.

**P2 · DSA-named device adaptation**. Throughput sampling and RPS/XPS application hardcoded `eth0/eth1`, which zeroes sampling and breaks configuration on modern OpenWrt devices with lan1/wan naming (DSA switch chips). Physical interfaces are now detected via sysfs and the WAN role is resolved through ubus → uci → default-route fallback; virtual carriers such as pppoe-wan are classified correctly.

**P2 · Atomic state writes**. The scene state file is now written via temp-file + atomic rename, so the polling front end can no longer read a half-written file.

**CI · Hardened version guard**. The `N/merge` ref from pull-request events previously slipped through the version guard and crashed the build. Only full `N.N.N` forms are accepted now, and the build script validates the version string against a character whitelist.

## Verification

413 unit tests green (scene classification 21→26, with new assertions for bare-IP direct hits, non-first IP rules, and protocol-mismatched port chains); 16/16 on-device e2e; core fixes were reproduced and verified on real hardware (bare IP classified `normal` before, `gaming` after). No new features; steering logic is unchanged. Upgrade and go.
