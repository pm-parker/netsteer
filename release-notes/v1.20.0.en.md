# v1.20.0 — Feedback loop: one-command diagnostics + leak fix

## Highlights

Turns bug reporting from chat logs into a single command. `netsteer-doctor` prints ten sections plus a VERDICT line, and pairs with the new issue templates to close the feedback loop — the step that takes this from a single-user internal tool to something strangers can actually run. Also fixes the sense-daemon leak caught on day one of 7×24 soak monitoring.

## Added

- **`netsteer-doctor` one-command diagnostics**: run it over SSH to collect everything needed to debug — package version, environment, dependencies, SQM state, offload flags, observation channel, scene engine, acceleration tunnels, steering state, config and log tail — ending with a `VERDICT` line (OK/WARN/FAIL). Known boundaries are flagged automatically: missing deps, flow-offload counter freeze, daemon leaks, degraded DNS observation, SQM disabled, game tunnel without IP, uninitialized state
- **GitHub issue templates**: bug report (doctor output required) and feature request, bilingual
- **"Troubleshooting & feedback" section in both READMEs**

## Fixed

- **sense-daemon process leak (caught on day one of 7×24 soak: 3 orphaned daemons on one box)**, fixed in four layers:
  - Function-level guard: daemon startup verifies pid file + `/proc/<pid>/cmdline` as dual evidence; direct invocation exits immediately (previously any path bypassing the init.d guard spawned another process and overwrote the pid file)
  - init.d gains a real `stop()`: the old `restart()=start()` meant a daemon survived every upgrade, forever running old code
  - apk postinst now runs `restart` instead of `start` so upgrades actually swap the daemon
  - The TERM trap now checks pid-file ownership before deleting: fixes a race where an old daemon's exit removed the *new* daemon's pid file during the upgrade window (busybox sh handles signals only after `sleep` returns, so the window lasts up to one poll interval)

## Tested

- On-device (NanoPi R5C / OpenWrt 25.12.6): daemon count = 1 after restart; direct `netsteer-qos sense-daemon` invocation returns exit code 0 with process count unchanged; doctor reports `VERDICT: OK` with numeric fields (SQM bandwidth, offload flags) matching raw audit output
- e2e extended by 2 checks (doctor ten-section assertions + direct-invocation guard), 16→18 all green; 413 unit assertions all green

## Known limits

- Doctor reports daemon leaks but does not recycle them (`/etc/init.d/netsteer restart` does); pre-existing leaked processes need one restart after upgrading to this version
- Observation-channel findings rely on the netsteer-qos env cache; right after a proxy core starts or stops, the channel shown by doctor may lag by one probe cycle
