# v1.21.0 — 场景注入 e2e + lint 门禁

## 版本特色

场景判定第一次有了自动化验证。以前改一次 `sense.awk` 的判定逻辑，只能靠人工在真机上制造流量再肉眼判断——现在有独立的注入测试：真实流量 → 观测面 → 引擎判定，端到端跑。

同时把 JS lint 接进 CI，存量未使用声明清零并设为门禁。

## 新增

- **`tests/e2e/inject_test.py` — 场景注入 e2e**（独立脚本，需双 pod 环境，无 pod 自动跳过）
  - streaming 场景：真实下载 `www.youtube.com`（`--resolve` 固定真实 IP 绕开 fake-ip，SNI 保留域名），轮询采样直到引擎产出 `ev_stream_dom`
  - download / gaming 场景：UDP 打 6881（BT 下载端口）/ 27015（Steam），切 conntrack 观测面后验证端口证据进引擎
  - 观测面改动后自动恢复 `auto`
  - 已挂进 `e2e.py --inject`（默认不跑，避免 CI 无 pod 环境误报）
- **`.oxlintrc.json` — oxlint 配置**：`_` 前缀视为有意忽略；`no-underscore-dangle` 关闭
- **CI lint 门禁**：`no-unused-vars` / `no-unused-expressions` 必须归零，否则 CI 失败

## 修复

- **JS 存量未使用声明清零（48 → 0）**
  - 27 处 `catch (e)` → `catch (_e)`
  - 16 处未使用参数/变量加 `_` 前缀
  - 4 个从未被调用的死代码函数删除：`leaseSuggestions` / `netdevParse` / `speedTier` / `tierFrom`
  - 1 处三元表达式副作用改写为 if/else
- **注入测试踩坑记录（已写入脚本注释）**
  - `netsteer-qos dnslog` 输出的是 JSON，判定引擎吃的是 TSV 七字段——必须走 `dnslog | qos_json2tab | exclude.awk | sense.awk`（`netsteer-qos sense` 是封装）
  - 注入流量必须真正经过路由器透明代理，否则 mihomo 连接表里没有该来源，域名证据拿不到
  - 连接关闭即出表，采样必须在注入进行中轮询
  - LAN→LAN 流量不过防火墙 conntrack，端口类证据必须打公网
