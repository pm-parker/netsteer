# v1.22.0 — Loaded-latency probe + thermal guard

## Highlights

### Loaded-latency probe (bufferbloat, honest-boundary edition)
New "Bufferbloat" card on the dashboard: one tap measures idle latency vs loaded latency. An 8-stream CDN download generates real downstream load, ping samples the same window, and both the delta and the measured load (load_mbps) are persisted.

- When load fails to ramp (<50 Mbps) the verdict is `weak` with an explicit "reference only" note — a direct lesson from field testing: a 0 ms delta with no load is a false negative
- Verdict tiers: stable(<10ms) / light(<30) / mid(<100) / severe(≥100)
- **Honest boundary**: CDNs rate-limit each stream to ~24 Mbps; on-device 8-stream load tops out around 200 Mbps — on gigabit links this validates shaping health and a capacity lower bound, not full-saturation bufferbloat (which needs flent-style external load). Stated plainly in both READMEs and the script header.

### Thermal guard
`netsteer-check` (per-minute cron) samples the hottest thermal zone:

- Values go to `/tmp/netsteer/health.json` (tmpfs — per-minute writes never touch flash; uci/log writes only on threshold crossings)
- ≥85°C: logged warning with 10-minute anti-spam
- ≥95°C: auto-downgrade to the steering profile (thermal protection beats throughput), incident log at `/etc/netsteer/incidents/thermal-*.log`; **no auto-restore** on cooldown (better-silent-than-wrong) — the UI tells you when to re-enable
- New "Device temperature" card on the dashboard: green normal / plain ≥85°C / red ≥95°C

### Other
