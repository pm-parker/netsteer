# v1.22.1 — Snapshots & rollback + persistent change audit

Priority-3 safety net: every config change is reversible, and the change timeline survives reboots.

## Snapshots & rollback (netsteer-snapshot)
- Auto-snapshot before write operations across four channels: mode switches, master toggle / device boost (qos), wizard apply, bulk device list
- Snapshot contents: full netsteer + sqm uci, firewall offloading field, mode at the time; stored at `/etc/netsteer/snapshots/`, 20 kept, 5-min same-label dedup (anti double-tap / self-heal spam)
- `restore <id|latest>`: uci restore → sqm restart → fw4 reload → netsteer-apply runtime re-align → **replays the nft rules layer** (p2p passthrough rebuilt per restored mode, game lane via qos reapply) — rules don't live in uci, a uci-only restore would miss them (found in device testing and fixed)
- Auto pre-restore snapshot before every rollback: rollbacks themselves are rollback-able; `/etc/config/*.pre-restore` fallback guards against import failure
- firewall is never wholesale restored (only the offloading field) — restoring the whole firewall package is too risky

## Persistent change audit
- `/etc/netsteer/history.log`: all save/auto/restore events + check's state-change lines; survives reboots (before v1.22.1 the /tmp copy vanished on reboot); rolls at 2000 lines keeping 800
- /etc is written only on actual state changes — no flash wear

## UI
- New "Snapshots & rollback" card on the expert page: snapshot count, latest id, last 6 timeline entries, and a rollback button behind a confirmation modal
